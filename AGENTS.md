# Vocab Learning App — web

Duolingo-style English vocabulary app for Thai speakers, built on the Oxford 3000.
**Read [`docs/SPEC.md`](docs/SPEC.md) before planning any non-trivial change** — it defines
the goal, the architecture, the current known-broken list, and the roadmap.

This repo is the **web** Worker. The API lives in the `backend/` git submodule
(`potatodevsr/vocab-backend`) and deploys as its own Worker.

## Architecture in one paragraph

Two Cloudflare Workers on one origin. The **web** Worker (Next.js 16 via
`@opennextjs/cloudflare`) forwards `/api/*` to the **api** Worker through a **service
binding** — no CORS, no public API hostname, first-party cookies. The api Worker is Hono
(routes generated by `prisma-generator-express` with `target = "hono"`, every operation
locked down by `prisma-guard`) talking to **D1** through `@prisma/adapter-d1`. Audio lives
in R2. Details and reasoning: `docs/SPEC.md` §2–3.

## Hard rules

1. **The client never sends a `userId`, an XP amount, a score, or a mastery value.** It
   reports what happened; the server decides what it's worth. Gameplay mutations go through
   the hand-written verbs in `docs/SPEC.md` §5.3, never through generated CRUD.
2. **No hand-written API response types.** Run `pnpm gen:api-types` against a running API
   and use the generated output. Duplicated shapes are why `lib/types.ts` and
   `lib/admin-api.ts` drifted from the schema.
3. **No hardcoded user-facing strings.** Everything through `next-intl`; keys land in both
   `messages/en.json` and `messages/th.json`. Thai is the primary audience — an untranslated
   `th` value is a bug, not a TODO.
4. **No Node-only APIs** in anything that runs on a Worker. `jose`, not `jsonwebtoken`;
   WebCrypto, not `bcryptjs`; `fetch`, not `http`.
5. **One `API_URL`.** `constants/config.ts` is the only place it is defined.
6. **Every route that fetches gets `error.tsx` and `loading.tsx`.** Server fetches throw by
   design; an unhandled throw is a white screen.
7. **Mobile-first.** Design at 390px. Desktop is the adaptation, not the baseline.
8. **Fetch by unit, never by level.** The API caps a single read (guard `take.max`), so
   "fetch the level and slice locally" silently truncates a 900-word level to the first
   page. Use `getWordsByUnit` / `getLevelWordCount` from `lib/oxford-words.ts`.
9. **API paths are lowercase and have no trailing slash.** Hono routes strictly, unlike
   the Express API it replaced: `/VocabWord` and `/vocabword/` both 404.

## Schema changes are a two-repo dance

The submodule means order matters: **API repo first** (migrate → deploy), then this repo
(regen types → use them), then commit the bumped submodule pointer. A green web build on a
stale submodule pointer means nothing.

## Testing — the commit gate

**Every code change must be reflected in the e2e suite, and nothing is committed until
`pnpm test:e2e` is green.** A change to user-visible behaviour updates its test in the
same change, not a follow-up.

The suite is full-stack: a real production Next build, the real Hono Worker on
`wrangler dev --local`, and a real D1 database. No mocked network, no stubbed API — the
rows a test creates are really committed.

```bash
pnpm test:e2e             # the gate. builds, boots API + web, runs everything
pnpm test:e2e:ui          # interactive runner
```

Ports are deliberately split so a test run can never touch what you are developing
against:

| | web | API | D1 state |
| --- | --- | --- | --- |
| `pnpm dev` | 3000 | 4000 | `backend/.wrangler/state` (real Oxford data) |
| `pnpm test:e2e` | 3100 | 4100 | `backend/.wrangler/e2e-state` (wiped + reseeded per run) |

Never set `reuseExistingServer: true` for the web server: it would let the suite run
against a `next dev` built for a different API and a different database, which is exactly
how a green run once lied.

Fixtures live in `e2e/support/fixtures.ts` and mirror
`backend/scripts/generate-e2e-seed.mjs` — change one, change the other. `SEED.mutableWord`
is reserved for tests that write; read-only tests must not assert on it.

## Commands

```bash
pnpm dev                  # next dev (expects the API on :4000 — see backend/AGENTS.md)
pnpm build                # next build (Turbopack) — must be green before any PR
pnpm exec tsc --noEmit    # must be clean
pnpm lint
pnpm extract:oxford       # regenerate data/oxford-3000-seed.json from the PDF
```

## Layout

```
app/[locale]/       learner-facing pages (en, th)
app/admin/          content admin, its own auth, not localised
components/ui/      shadcn primitives — generated, don't hand-edit
components/         feature components
lib/                api clients, quiz/SRS logic, pure helpers
i18n/, messages/    next-intl routing + strings
proxy.ts            route protection (Next 16 middleware)
backend/            → git submodule: the api Worker
docs/SPEC.md        goal, architecture, audit, roadmap
```
