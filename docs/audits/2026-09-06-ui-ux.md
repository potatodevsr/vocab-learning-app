# UI/UX audit — 6 September 2026

## Verdict and scope

**Not ready for full UX sign-off.** The visual system is recognisable and public placement completes, but recovery, saved-state messaging and teaching feedback have actionable defects.

Reviewed web `b4fe21b`, backend `ba930ec`. Both worktrees were clean at the beginning and end of inspection. No application files changed, no commits, no deployment. This report is stored in `docs/audits/2026-09-06-ui-ux.md` within the web repository.

Evidence labels:

- **Chrome:** directly observed in the user's Chrome against the local app and real local corpus.
- **Source:** traced in current implementation; not reproduced in an authenticated browser session.
- **Chrome + source:** visible symptom corroborated by implementation.

Chrome coverage: Thai home → A1 curriculum → unit-1 practice entry; search entry with `?q=about`; English login with a unit-45 return path → Thai language switch; Thai placement start → all 12 answers → recommendation; English `about` word page, speech-button activation and character-control activation. Mobile testing reached a measured CSS viewport of 390 × 844; desktop login was visually inspected. The temporary viewport override was reset.

Limits: existing anonymous trial state blocked a new practice trial. There was no disposable authenticated account available during this pass. Full saved-session completion, account creation, reminders, notifications, account export, screen-reader operation, audible speech correctness, production performance and complete console cleanliness are **not verified**. Browser inspection of search stalled, and a separate 15-second request for `/search-index.json` timed out. The local Next process was using approximately 300% CPU while the API curriculum request answered in 25 ms. That is development-environment evidence, not a production speed claim. The full E2E gate was not rerun for this read-only audit.

## High priority

### UX-01 — An abandoned anonymous trial can strand the learner for up to 30 days

**Evidence: Chrome + source.** Opening `/th/english/a1/unit/1/practice` displayed “มีแบบฝึกหัดที่ยังทำไม่เสร็จอยู่” and only a Back action. Chrome's local-app tab inventory contained no original resumable trial tab.

The UI resumes exclusively from per-tab `sessionStorage`. Without that cache it calls `/practice/start`; the backend refuses another trial while the existing cookie points to an unfinished, unexpired trial. Its lifetime is 30 days. There is no public resume endpoint/UI that reconstructs that trial in a new tab. The “try again in a little while” explanation is not a reliable recovery path. A rate-limit 429 also gets the same misleading “another trial is open” copy.

Sources: `components/practice/practice-session.tsx:124`, `:166`, `:334`; `backend/src/practice.ts:37`, `:252`.

Fix: return a resumable server-backed session and scope; offer an explicit Resume action. Distinguish active-session conflicts from rate limiting, with an honest retry time. Test close-tab/reopen, fresh-tab entry, changing unit and exhausted rate limits—not only same-tab reload.

### UX-02 — Today cannot resume review/comeback/mistakes sessions

**Evidence: Source.** Start a non-normal session, leave for Today, then select Continue session. The link preserves level/unit but omits `mode`; `/learn` defaults to normal. The backend rejects the incompatible open session with 409, which becomes a generic error whose Retry repeats the same request.

Sources: `components/play/today-card.tsx:19`; `backend/src/progress.ts:817` omits mode from the selected session; `backend/src/session.ts:719`, `:747`.

Fix: include authoritative mode in the summary/generated API types and resume URL, or resume by session ID. Test all four modes through Today, not merely visibility of its CTA.

### UX-03 — Saved-session refresh starts the UI at question 1 again

**Evidence: Source.** `MixedSession.boot()` always sets `answered` to `[]`. The resumed start response returns the original items but no answered offset/history, and the component never reads the existing status endpoint. After answering several items and refreshing, the learner must replay answered questions. The backend's idempotency preserves the original verdict, so choosing something different during replay can produce feedback about the previous answer.

Sources: `components/practice/mixed-session.tsx:118`; `backend/src/session.ts:736`, `:949`, `:1238`.

Fix: hydrate the current index and prior verdicts from authoritative state. Preserve already recorded answers; do not simulate resume by asking them again. Assert question N, progress pips and score after refresh/save-and-leave.

### UX-04 — Wrong multiple-choice answers do not teach the correct answer

**Evidence: Source.** In the mixed session, only a correctly selected option receives the green treatment. A wrong choice shows “Not quite — this word will come back for review,” but never identifies the correct meaning/word. Only spelling gets an actual correction. This makes the main learning loop less informative than the anonymous trial.

Sources: `components/practice/mixed-session.tsx:550`, `:634`; `backend/src/session.ts:937`; `messages/en.json:906`.

Fix: return the correct answer after grading, highlight and explain it without leaking it before submission. Test a deliberately wrong answer and assert the actual correction, not just an icon and generic feedback.

### UX-05 — Placement still serves corrupt Thai content

**Evidence: Chrome + source + read-only API check.** During the completed 12-question placement, a Thai answer option was literally `ang`. A published B1 corpus read confirmed `age`, unit 1, has `meaningTh: "ang"`.

Placement selects any non-empty meaning and emits it verbatim; it does not use the trusted-content filtering introduced for practice. A malformed distractor changes question difficulty; a malformed target makes the question invalid.

Source: `backend/src/placement.ts:166`, `:195`.

Fix: apply the existing mechanical content checks to both targets and distractors before sampling, paging past rejected rows as necessary. Do not auto-approve semantic quality. Add production-shaped corrupt-content fixtures for placement, not only practice.

### UX-06 — “Saved to your account” does not mean the save succeeded

**Evidence: Source.** The trial result renders the saved checkmark on `isAuthed || claimed`, including while the claim request is pending or after it fails. Claim errors are swallowed. Additionally, `attemptClaim` depends on `claiming`; toggling that state changes the effect dependency and can repeatedly retry a persistent failure without a bounded policy.

Sources: `components/practice/practice-session.tsx:267`, `:282`, `:413`.

Fix: separate saving, confirmed saved, expired and retryable-failure states. Require server confirmation or a confirmed already-claimed result before displaying success; bound retries. Test offline/500/expired-claim cases for signed-in learners.

## Medium priority

### UX-07 — Matching instructions describe an interaction that does not exist

**Evidence: Source.** Copy says “Tap the word, then tap its match,” but the word is a plain heading. The first tap on an answer silently flips a ref without any visual selection; the next answer tap submits. Keyboard selection bypasses that first tap. Existing E2E helpers explicitly tap the same answer twice, encoding the workaround rather than validating the instruction.

Sources: `components/practice/mixed-session.tsx:492`, `:571`; `e2e/learn.spec.ts:24`; `messages/en.json:901`.

Fix: make the word a real pick-up control with a visible selected state and equivalent keyboard behavior, or make this an honest single-tap matching choice. Test by following the visible instruction.

### UX-08 — Language switching destroys query and authentication continuity

**Evidence: Chrome + source.** From `/en/auth/login?from=%2Fen%2Flearn%3Flevel%3DA1%26unit%3D45`, pressing TH navigated to `/th/auth/login`. Its Google link then carried only `from=/th`, and Register also lost the original destination. On search with `?q=about`, both language links omitted `q`.

Source: `components/language-switcher.tsx:66`.

Fix: preserve an allowlist of safe query state and deliberately map locale-qualified return destinations. Test query-bearing search and auth pages in both directions, including clicking the already-active locale.

### UX-09 — Header sign-in/signup drops the learner's current page

**Evidence: Chrome + source.** Word, curriculum and trial headers link directly to `/auth/login` and `/auth/register`, without `from`. The form's fallback is home. This differs from the contextual result CTA and protected-route redirect, which do preserve intent.

Sources: `components/user-navbar.tsx:85`, `:92`; `lib/return-path.ts:86`.

Fix: use a validated current path/query return target, with an active-session continuation target where appropriate. Test entering auth from a specific word, a tail unit and a result.

### UX-10 — Placement's “Save progress” action saves no placement result

**Evidence: Chrome + source.** Placement completed and offered “บันทึกความคืบหน้า,” linking only to `/th/auth/register`. Its result exists only in component state; no result or recommended-level continuation is carried into registration, and placement itself writes no account progress.

Sources: `components/practice/placement-test.tsx:142`; `backend/src/placement.ts:10`.

Fix: either preserve and apply the recommended starting point through registration, or relabel the action accurately as account creation and retain an onward link to the recommended level. Test a non-A1 recommendation through the complete handoff.

### UX-11 — Active public tests retain a marketing-page layout on mobile

**Evidence: Chrome + source.** At 390 × 844, the placement's first question showed three complete answers while the fourth ran below the viewport. The sticky two-row header and large introductory band remained after Start. Public practice similarly retains global navigation and its hero. This consumes question space and offers unrelated exits during an active task.

Sources: `components/app-bar.tsx:27`; `components/site-footer.tsx:17`; `app/[locale]/english/test/page.tsx:105`; unit-practice page at `:104`.

Fix: retain informative public landing content before starting, then switch to a compact active-session shell and bring the question into view. Verify all four answers and the action area at 390 × 844, including long Thai options and keyboard-open states.

### UX-12 — Close dialogs are not keyboard-modal; timed rounds keep running underneath

**Evidence: Source.** Practice, mixed-session and checkpoint confirmations are ordinary `div` elements with `aria-modal`, with no focus placement, trap, inert background or focus restoration. Escape support alone is not a modal implementation. Mixed-session speed countdown also ignores `showClose`, so a round can time out while the learner is deciding whether to leave.

Sources: `components/practice/practice-session.tsx:603`; `components/practice/mixed-session.tsx:686`, `:242`; `components/practice/checkpoint-session.tsx:674`.

Fix: reuse the accessible dialog primitive, restore focus on dismissal, and pause the timer while the confirmation is open. Test Tab/Shift+Tab containment, Escape, restored focus and opening the dialog at one second remaining.

### UX-13 — Public practice's Continue button moves when feedback appears

**Evidence: Source.** Feedback is conditionally inserted inside the card above Continue; no space is reserved. Despite the comment claiming the button never moves, feedback necessarily increases the content height. The mixed-session component has a reserved feedback area, but the anonymous trial does not.

Source: `components/practice/practice-session.tsx:549`, `:581`.

Fix: share a stable feedback/action layout. Assert the Continue position before and after correct and wrong feedback at mobile width, including a long corrected meaning.

### UX-14 — Search has no recovery after a transient index failure

**Evidence: Source; live search remained loading during this audit.** `requested.current` is set before fetching and never reset on rejection. There is no Retry control. Further typing cannot initiate another request. An unresolved request also leaves the loading state without a timeout or recovery message.

Source: `components/word-search.tsx:76`.

Fix: add a bounded request timeout and explicit retry that resets failed/requested state while preserving the query. Test one failed load followed by a successful retry; do not treat the observed dev delay as proof of production latency.

### UX-15 — A review API failure is presented as a clean mistake bank

**Evidence: Source.** The API client returns null on non-OK HTTP responses; the page maps null to `[]` and renders the celebratory no-mistakes state. A server error or expired session therefore becomes false learning feedback instead of recovery UI.

Sources: `lib/progress-api.ts:162`; `app/[locale]/review/page.tsx:41`.

Fix: distinguish empty-success, authentication failure and service failure. Test 401/500 separately from a genuine zero-item response.

### UX-16 — Reminder rollback can display a time that was never saved

**Evidence: Source.** Clicking an hour optimistically updates `hour`; on failure the catch block changes only opt-in, never restoring the previous hour. It can also use the original opt-in value rather than the most recent successfully saved value. After enabling reminders during this mount, a later failed hour change may unexpectedly hide the controls. Old saved feedback is not cleared at the start of a new request.

Sources: `components/play/reminder-settings.tsx:67`, `:80`, `:131`, `:182`.

Fix: keep a last-confirmed settings snapshot and restore both fields after failure. Make saving/saved/error mutually exclusive. Test successful enable followed by a failed hour change.

### UX-17 — Weekly goal saving provides neither failure feedback nor an updated summary

**Evidence: Source.** The save handler uses `try/finally` without catch, so failure produces no inline explanation. On success the prompt disappears without refreshing the server-rendered Today summary; the goal card can continue to show the pre-save state until navigation/reload.

Source: `components/play/weekly-goal-prompt.tsx:46`; `components/play/today-card.tsx:106`.

Fix: show a retryable failure and update/invalidate the summary after successful save. Test the visible goal card, not just disappearance of the prompt.

## Smaller polish and test gaps

- Thai home “ดูวิธีเรียน” (see how learning works) launches practice rather than the how-it-works page. Rename it to the activity or route it to the explanation. Source: `components/home/marketing-home.tsx:191`.
- Login lacks the password-reveal affordance already supplied by registration. This is a consistency improvement, not a release blocker.
- Placement changes the question immediately without moving focus or announcing the new prompt. Custom radio groups also lack native arrow-key/roving-focus behavior. Add assistive-technology verification; a hover sweep cannot establish keyboard or screen-reader usability.
- The 40-result search limit is reported as a count with no indication of truncation; consider “first 40 matches” or a refine-search hint.
- Current tests miss continuity and failure semantics: matching is double-tapped by the helper; close tests inspect opening/cancel rather than leaving/resuming; the generic 429 test expects “trial already open” even for rate limiting; successful-save tests do not exercise failures; the stable-button test covers mixed sessions but not public practice.

## What worked in this pass

- Thai home and A1 curriculum navigation rendered; the level page showed 758 words, 45 units and links through unit 45.
- The unit-1 practice URL was a rendered practice page, not the historical 404. Its active-trial recovery state is the problem recorded above.
- Placement started anonymously, advanced through all 12 questions and displayed a scored A1 recommendation with a public level CTA. Random audit choices were not an assessment of the auditor's language ability.
- Locale switching changed the interface language, exposing the precise query-continuity defect above.
- The English word page rendered Thai speech and character controls. Both were activated; audible output and the completeness of their assistive feedback were not established.
- The header SVG mark remained recognisable at mobile size. No logo change is needed to address the functional findings.

## Recommended fix and verification order

1. Repair trial/session resume and mode continuity; then make save status truthful.
2. Correct answer feedback, matching behavior and placement content selection.
3. Preserve context through locale/auth/placement handoffs.
4. Unify active-session layouts and accessible dialogs; cover failure states for search and settings.
5. Run targeted full-stack regressions, then the repository's release gates, and repeat Chrome checks with a disposable authenticated account at 390 × 844 and desktop size. Require a demonstrated path through refresh, wrong answers, interruption and failed writes before calling the experience polished.
