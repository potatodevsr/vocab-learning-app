# UI/UX audit — 7 September 2026

## Verdict and scope

**Closer, and still not sign-off.** Twelve defects were fixed in this pass — seven found by
driving the app, five more by reading it — including the one the previous round put first.
What remains open is mostly *teaching* rather than *chrome*: a wrong answer still does not
say what the right one was, `/review`'s mistake bank never forgets, and the onboarding the
lifecycle document specifies still does not exist in any form a learner can see.

This is the second and third round, in one file. The first is
[`2026-09-06-ui-ux.md`](2026-09-06-ui-ux.md); its `UX-01`–`UX-17` identifiers are kept, and
new findings here continue from `UX-18`. Where a round changes the status of an earlier
finding it says so against that finding's own number. The browser pass is below; the
source-level sweep that follows it starts at `UX-34`.

Reviewed web `b4fe21b` plus the working tree this pass produced; backend unchanged (no API
or schema change was needed for anything fixed here). Driven against `pnpm dev` on :3000
with the API Worker on :4000 and the real local D1 corpus — 2,675 published words, 758 in
A1. Disposable accounts were registered through the real form, so the authenticated
coverage the previous round could not reach is covered here.

Evidence labels follow the first round:

- **Browser:** reproduced by driving the running app.
- **Source:** traced in the implementation, not reproduced live.
- **Browser + source:** symptom observed, cause read.

Coverage this pass: landing (th/en) → register → Today → mixed session (answered, resumed,
quit, keyboard) → checkpoint gate → progress → profile → review; the public content set
(hub, level, unit, word, A–Z, search, alphabet, pronunciation, minimal pairs, phrasal
verbs, placement, trial); 404s; and a rendered link crawl of 96 internal URLs. Viewports
320, 360, 390 and 1440 CSS px — 390 is the design width (`SPEC.md` §6.3), the two narrower
ones are the phones this audience actually holds and had never been measured.

Not verified: screen-reader operation, audible speech correctness, production performance,
push and reminders, admin beyond one missing route state, and anything requiring the
production corpus. Dev-server timings in here are not production latency claims.

## Fixed in this pass

### UX-03 — Saved-session refresh started the UI at question 1 again *(now fixed)*

**Browser + source.** The first round traced this; here is what it does to a learner.

`POST /progress/session/start` returns the open session's items and no answer state, and
`MixedSession.boot()` reset `answered` to `[]`, so a reload re-asked questions the server
had already graded. The server grades an already-answered index idempotently and replays
its stored verdict, and the client rendered that replay as the result of the new pick. On
an account whose item 1 had been answered correctly, `about` with the options
`เมษายน / เกี่ยวกับ / ใดๆ / อากาศ`, selecting **เมษายน** (April) produced a green tick on
that option and **"ถูกต้อง!"**. The app taught the wrong meaning, with a celebration —
directly under a close dialog whose copy promises "คำตอบที่ตอบไปแล้วถูกบันทึกไว้แล้ว
กลับมาทำต่อภายหลังได้".

Fix: `lib/session-api.ts` gains `getSessionStatus()` — `GET /progress/session/:id` already
existed and was already in the generated types — and `boot()` opens the session at the
first unanswered item. Items answered before this mount are drawn as *done* with a neutral
pip, never as right or wrong: `answeredCount` carries no verdict and nothing may invent
one. A replayed verdict, should one still arrive, is labelled "ข้อนี้ตอบไปแล้ว…" instead of
being dressed as a grade. The result headline prefers the server's `correctCount`/`total`,
which a resumed session cannot compute locally.

Verified: reload mid-session now reopens at item 2 of 8 with the same word, and the answer
posts against index 1 with `duplicate: false`.

Tests: `e2e/learn.spec.ts` — "returning to an open session resumes at the first unanswered
item", "an item answered before this visit is drawn as done, not as right or wrong".

### UX-09 — Header sign-in/signup dropped the learner's current page *(now fixed)*

**Browser + source.** The bar linked to bare `/auth/login` and `/auth/register`, so anyone
who pressed "log in" from a word page or a tail unit was returned to the home page. The bar
now carries a validated, locale-qualified `?from=` (`components/app-bar.tsx` →
`components/user-navbar.tsx`); `lib/return-path.ts` already refuses anything that is not a
same-origin learner path. The query string is deliberately not included: reading it needs
`useSearchParams`, which would opt every page that renders the bar out of static
prerendering. Verified from `/th/english/words/abandon`: all three header auth links carry
`from=%2Fth%2Fenglish%2Fwords%2Fabandon`. Test in `e2e/auth.spec.ts`.

### UX-18 — The signed-out app bar fell off a 360px screen *(fixed)*

**Browser.** At 390px the bar fitted with 8px to spare. At **360px and 320px** its contents
measured 382px: `document.scrollWidth` exceeded the viewport, the whole page scrolled
sideways, and **"สมัครสมาชิก" — the one control the landing page exists to reach — was cut
off at the right edge.** Thai labels are why the 390px measurement was not evidence for
360.

Fix: below `sm` the sign-in pill leaves the bar and joins the mobile section row, so the
bar keeps the sign-up CTA and sign-in stays one row below it, still one tap away. Measured
after: no page overflow and no off-screen control at 320, 360 or 390, in both locales.
Tests in `e2e/design.spec.ts` cover all three widths in both locales plus "a phone can still
reach sign-in".

### UX-19 — A form filled before hydration was thrown away *(fixed)*

**Browser + source.** Both auth forms are controlled: every keystroke is supposed to arrive
through `onChange`, and between first paint and hydration there is no `onChange`. Measured
with script delivery delayed by 6s — an ordinary mid-range Android on a slow connection —
the register form held all five typed values in the DOM and still reported
`isFormValid === false` **twelve seconds later**: five visibly complete fields above a
permanently disabled button, with nothing on screen to explain it. The same gap swallows a
password manager's autofill, which lands before hydration by design; on the login form the
same state would post an empty password and answer "wrong email or password".

Fix: `lib/use-prefilled-form.ts` adopts what the DOM already holds, on mount, in both
forms. Re-measured under the same 6s delay: values intact, button enabled. Test in
`e2e/auth.spec.ts`.

### UX-20 — The footer offered logged-out visitors three dead ends *(fixed)*

**Browser + source.** `components/app-bar.tsx` stopped showing `/learn`, `/quiz` and
`/review` to anonymous visitors because all three 307 into the login form — and Next
prefetched every one of them. `components/site-footer.tsx` kept its own copy of the list,
so every public page still ended in the three links its own header had removed. Signed out,
that column now offers the trial, the one thing in it that works without an account.
Test in `e2e/seo-pages.spec.ts`.

The same crawl that found this checked 96 internal links across the home, hub, level, word,
FAQ and about pages: no 404s, no broken targets, and those two gated redirects were the
only non-200 answers on the whole surface.

### UX-21 — The authenticated home had no `h1` *(fixed)*

**Browser.** `/[locale]` for a signed-in learner opened on a chip and a button: nothing for
a screen reader to announce and nothing to jump to, on the screen every session starts
from. The greeting stamp is now the page's `h1`. Test in `e2e/today.spec.ts`.

### UX-22 — Thai letters were 14×34px targets *(fixed)*

**Browser.** The alphabet table rendered each character as a bare inline link — a 14px-wide
hit area, forty-four times over, under the 24px WCAG 2.2 (2.5.8, AA) floor, on a page
written for phones. The link box now has a 44px minimum without changing how the row looks.
Test in `e2e/design.spec.ts`.

### UX-23 — Two ways of writing the same return path *(fixed)*

**Browser.** `middleware.ts` percent-encodes `?from=`; the server-side redirects in
`/progress`, `/profile` and `/review` wrote it raw, so the same wall produced
`?from=%2Fth%2Ftoday` down one path and `?from=/th/review` down another. Both happened to
work because the values are plain paths; the first one that is not would not. All builders
now encode.

## Still open

### UX-04 — A wrong answer still never says what the right one was *(confirmed in browser)*

**Browser.** On a fresh account, `about` answered with `สนามบิน` returns
"ยังไม่ใช่ — คำนี้จะกลับมาให้ทบทวนอีก" and nothing else. The learner is told they were
wrong and is not told the meaning; the item returns later with the same four options and no
new information. This is `todo.md` Stage 04 and the first round's `UX-04`, and it is now
the largest teaching gap in the product: after this pass, the session's *mechanics* are
sound and its *instruction* is still missing.

### UX-24 — Onboarding copy is translated and never rendered

**Source.** `Today.directionConfirm`, `directionSwitch`, `startingPointTitle`,
`startFromBeginning`, `quickLevelCheck` and `chooseLevel` exist in both `messages/en.json`
and `messages/th.json` and have no caller anywhere in `app/` or `components/`. Registration
lands straight on the Today card: no direction confirmation, no "where should we start?" —
`LEARNER-LIFECYCLE.md` §3.4 in full, including the placement handoff the first round
recorded as `UX-10`. Ship it or delete the keys; a translated string with no caller is a
promise the codebase makes to its next reader and breaks.

### UX-25 — The landing hero advertises a session the product does not have

**Browser + source.** The desktop hero's phone mock shows a word card with
**"รู้แล้ว / ทบทวนทีหลัง"** — self-rating buttons. The real session is four-option
recognition with one continue button. The copy comes from the `Lesson` namespace, whose
route `todo.md` Stage 06 schedules for deletion, and
`components/hero-word-illustration.tsx` is that namespace's only remaining caller. The
first thing a visitor sees is an interface they will never meet.

### UX-26 — The free trial sits four folds below the page that advertises it

**Browser.** `/{locale}/english/{level}/practice` opens on a hero promising "5 questions,
60–90 seconds, no signup", then spends the next screen on ten sample words. The practice
card starts at y≈1,587 of a 3,867px page, and nothing in the hero starts it. This is the
acquisition path's own landing page. Related to the first round's `UX-11`, but the problem
here is order, not shell.

### UX-27 — A new learner's progress page is a 3,185px column of zeros

**Browser.** Four full-width cards at 390px, each holding a single "0" and a label.
`SPEC.md` §6.3 #5 asks for drawn empty states; this is the dashboard-shaped opposite. A 2×2
tile grid plus one drawn "nothing yet — here is the first thing to do" would put the same
information above the fold.

### UX-28 — The word page says the meaning twice

**Browser.** `/{locale}/english/words/{word}` puts "แปลว่า ละทิ้ง" in the hero and a
"ความหมายภาษาไทย: ละทิ้ง" panel directly beneath it. `SPEC.md` §6.1 rules this out for the
lesson card ("do not repeat the large answer in a second panel"); the page that teaches one
word deserves the same rule, and the space belongs to what the hero does not already say.

### UX-29 — Hydration mismatch on both auth pages

**Browser.** `/{locale}/auth/login` and `/auth/register` log "A tree hydrated but some
attributes of the server rendered HTML didn't match… This won't be patched up" against the
`Card` primitive's `class`. The likely cause is the shadcn card's arbitrary variant
`has-[>img:first-child]`, which SSR emits entity-escaped (`has-[&gt;img…]`).
`components/ui/` is generated and not hand-edited, so this needs a decision rather than a
patch — but a permanent React warning on the two pages every account is created through is
worth one.

### UX-30 — The profile leads with a data export

**Browser.** The hero's `h1` is the raw username (`a1788710057896`) although registration
collected a name, and the first card beneath it is "download JSON / download CSV". Rights
and privacy work put the export there; a learner opening their profile is looking for their
streak, their goal and their course.

### UX-31 — The two 404s send you to different places

**Source.** `app/[locale]/not-found.tsx` offers `/english/a1`; `app/global-not-found.tsx`
offers `/{locale}` — while its own comment says "a reader should not be able to tell which
of the two answered them".

### UX-32 — A signed-in learner can reach the Today card at two URLs

**Browser + source.** `app/[locale]/today/page.tsx` is the rewrite target `middleware.ts`
uses for `/`, and its header comment says a directly-typed URL "is treated as a protected
path by the same middleware and lands on login". It does for a signed-out visitor; with a
valid session a typed `/th/today` renders the page, byte-identical to `/th`. Metadata is
`index: false`, so this costs nothing in search — it is one redirect away from matching
what the file says about itself.

### UX-33 — Smaller polish

- The search page's zero state is the line "พบ 0 คำ": no suggestion, nothing drawn.
- The skip link is the only control in the app whose focus ring is the browser default;
  every other control draws the house 4px ink outline.
- `app/admin/` has no `loading.tsx`. Admin is exempt from localisation, not from route
  states.
- On a unit page the first word sits at y≈677 of an 844px screen under a 126px sticky
  header, so the list a search visitor came for begins in the last 40px of the fold. The
  hero band above it is 507px of chip, title, one sentence and one button.

## What was verified working

Recorded so a later round does not re-litigate them.

- **Reduced motion** is honoured: `prefers-reduced-motion: reduce` leaves
  `document.getAnimations()` empty on the landing page.
- **The desktop session fits** 1440×900 with no vertical scroll (`SPEC.md` §6.1).
- **Keyboard in a session**: 1–4 select and submit, Enter continues, Esc opens the close
  confirmation. (Its dialog is still not focus-trapped — first round's `UX-12`.)
- **Quitting a session** confirms with save-and-leave rather than discard-only, and now the
  save it promises is real.
- **The locale switch preserves the path** on content pages:
  `/th/english/words/abandon` → `/en/english/words/abandon`. (Query state is still dropped —
  first round's `UX-08`.)
- **Focus is designed** on session controls: 4px ink outline plus the offset block.
- **No horizontal overflow** on any audited public route at 390px, and now at 360 and 320.
- **The checkpoint lock screen** states the requirement and offers the practice that clears
  it.
- **Link integrity**: 96 internal links crawled, no 404s.

## Method

- Playwright (the repo's own `playwright@1.61.1`) driving Chromium against `pnpm dev`, with
  fold and full-page screenshots at 320/360/390/1440.
- Per-page instrumentation for document overflow, controls outside the viewport, hit-area
  sizes, text under 12px, clipped text nodes, `h1` count, unnamed controls and console
  errors.
- Real accounts registered through the real form; sessions answered through the UI with the
  API's responses read off the wire.
- Slow-device conditions simulated by delaying every `*.js` response, which is how `UX-19`
  was found.

## Third pass — a source-level sweep (UX-34 onward)

The two passes above drove the app. This one read it: ten surfaces, one reader each, every
finding then handed to a skeptic whose job was to refute it against the same files (8 of 50
died there). Nothing here was reproduced in a browser unless it says so, and each entry
names the code it came from. Five were confirmed by hand and fixed in this pass; the rest
are open.

### Fixed

**UX-34 — `Enter` spent the session's one typed item on an empty answer.** *(verified by
hand, fixed)* The keydown branch in `components/practice/mixed-session.tsx` and
`checkpoint-session.tsx` called `submitSpelling()` with no emptiness guard, while the Check
button beside it is `disabled` on exactly that condition. `Enter` is the key the three cards
before the spelling item have just taught as "continue", so one muscle-memory press posted
`""`, the server graded it wrong, and the word lost a mastery rung — on the one item type
that never degrades away (`backend/src/mastery.ts` fixes it at index 3 of 8, and index 2 of
5 in a checkpoint, where pass is 4 of 5). Both keyboard branches now carry the button's
guard. Test: `e2e/learn.spec.ts` — "Enter does not spend a spelling item on an empty
answer".

**UX-35 — The checkpoint and the trial drew a replayed verdict as this answer's grade.**
*(verified by hand, fixed)* The other half of `UX-03`. `backend/src/checkpoint.ts` and
`backend/src/practice.ts` both return `duplicate: true` with the stored verdict rather than
re-grading, and both clients ignored the flag — `lib/checkpoint-api.ts` even documents it in
a comment its component never reads. In the trial the path is reachable without a second
tab: a committed answer whose response is lost sends the learner to the error screen, whose
retry reopens the same item from cache. Both now render the mixed session's neutral
"already answered" branch, and the trial no longer paints its green tick on an option the
learner did not choose. Test: `e2e/checkpoint.spec.ts` — "a replayed verdict is not drawn as
the grade for the answer just given".

**UX-36 — A failed clip erased the only prompt a listening item has.** *(verified by hand,
fixed)* `components/play/word-audio.tsx` hid itself for good on a media error, and the
`failed` flag was component state on a component the session reuses across items — so one
dead file also removed the speaker from every word after it. On `listen-choose` the player
*is* the question (the server withholds the word by design), which left four Thai options
and nothing to answer about. The state now resets with the source, and the control takes an
`essential` flag: where the clip is the prompt, a failure keeps a pressable retry instead of
vanishing. Test: `e2e/audio.spec.ts` — "a clip that will not play leaves the listening item
answerable".

**UX-39 — An API outage was read as "you are signed out".** *(verified by hand, fixed)*
`getTodaySummaryWithToken`, `getProgressSummaryWithToken` and `getMeWithToken` collapsed
every non-2xx into `null`, and all three callers read `null` as "no session": Today fell
through to the *marketing page*, Progress and Profile redirected to the login form. But
`middleware.ts` verifies the JWT locally before those pages run, so the learner is signed in
by construction — a 500, a 429 or the `1102 Worker exceeded resource limits` this deployment
has actually returned logged them out of their own app and offered a login that could not
succeed while the API was the thing that was down. Now only 401/403 mean "signed out";
everything else throws into the `error.tsx` each of those routes already has. Tests:
`e2e/unit/client-wrappers.spec.ts` — 500/429/503 reject, 401 still returns `null`.

**UX-55 — Eight public error boundaries printed translation keys at the learner.**
*(verified by hand, fixed)* `components/route-error.tsx` takes its namespace as a *prop*, so
the literal-namespace scan in `e2e/unit/messages.spec.ts` could not see its keys — and none
of the five namespaces its eight callers pass (`Search`, `MinimalPairs`, `PhrasalVerbs`,
`Pronunciation`, `AlphabetLetter`) carried `errorTitle`, `errorBody` or `errorRetry` in
either locale. next-intl falls back to the key path, so a learner whose page had just failed
was shown "Search.errorTitle". All 30 strings are written, and the guard now scans
`<RouteError namespace="…">` too, so the next boundary cannot ship the same way.

### Open — the learning loop

**UX-37 — The mistake bank never forgets.** `incorrectCount` on `UserWordProgress` is
monotonic: four writes increment it (`backend/src/session.ts`, `progress.ts`, `practice.ts`)
and nothing ever decrements, zeroes or deletes it, while membership of `/progress/mistakes`
is `status = "review" OR incorrectCount > 0`. A word answered wrong once in week one is in
the mistake bank forever, however many times it is later answered right — so `/review`'s
promise ("the words you got wrong") is false, and it grows monotonically for every learner.
Backend fix, so it is the two-repo dance.

**UX-38 — An empty review session is congratulated.** `backend/src/session.ts` returns a
deliberate `{ sessionId: null, itemCount: 0, items: [] }` for "nothing to do";
`mixed-session.tsx` folds `itemCount === 0` into `phase: "result"`, which is unconditionally
celebratory — "Session complete · 0 of 0 recalled · Nice work". `/review` can route straight
into it, because its count and the session picker use different filters (the page counts
published rows, the picker also requires a non-empty `meaningTh` and a matching wordlist).
`LEARNER-LIFECYCLE.md` §3.7 asks for the opposite: "on a day with nothing due the app says
so and offers a warm-up rather than inventing work".

**UX-47 — A failed placement score strands the learner on question 12.** On the last item
`placement-test.tsx` sets an error and clears `busy`; `result` stays null, so the only
control left re-answers the question they have already answered, overwriting it.

**UX-50 / UX-51 — Three surfaces, three different answers to "how many words do I owe?"**
`/progress/mistakes` returns `total: rows.length` after `take: 50` — a page size labelled as
a total — while `/progress/summary` counts differently again; and `/progress` and `/profile`
answer "how much of the Oxford 3000 do I own" from two different definitions of *strong*.

**UX-52 — Setting a weekly goal re-scores every past week.** The streak is recomputed from
raw activity against whatever `goalDays` is *now*, and the column is a bare `Int?` with no
effective-from date, so raising a goal retroactively breaks weeks the learner had already
earned.

**UX-48 / UX-49 — The card lies about what language its text is in, and reverse-direction
items keep forward-direction copy.** Prompts carry no `lang` attribute in any of the three
engines, so a screen reader reads Thai glosses with English phonology (and the Thai looped
face is selected by `lang` in `globals.css`); and a `meaning-to-word` item is still
introduced with "What does this word mean?".

### Open — the shell and the account

**UX-45 — Every signed-in page is served the signed-out shell until `/api/user/me`
answers.** `lib/use-session.ts` returns a `resolved` flag documented as existing "so a caller
can tell 'still loading' from 'definitely nobody'" — and it has no caller. Both the app bar
and the footer read `signedIn` alone, so a learner's own Today card is server-rendered with
"log in / sign up", three missing nav links and the anonymous footer column, and swaps after
hydration. Worth stating plainly: the clean fix is for the server to read the `signed_in`
cookie in `app/[locale]/layout.tsx` and seed the shell — but a layout that reads cookies is
a layout that cannot be statically rendered, which is exactly the ISR/KV behaviour
`AGENTS.md` rule 11 depends on. That trade is a product decision, not a refactor.

**UX-40 — Log out cannot fail.** `userLogout` is the only `/user/*` client that never checks
`res.ok`; the navbar clears local state and navigates regardless, so a failed logout looks
exactly like a successful one — on a shared phone.

**UX-41 — The service worker caches the signed-in home.** The private-route fence in
`public/sw.js` needs a second path segment, so `/th` and `/en` — which is where a signed-in
learner's Today card lives, and the installed app's launch URL — fall through to
`networkFirst` and are cached. That is `AGENTS.md` rule 14 exactly: "a stale profile page on
a shared phone is a bug nobody can see".

**UX-42 — One address, two accounts.** Registration and password login match `email`
verbatim; magic link and Google normalise with `trim().toLowerCase()`. `Bob@x.com` and
`bob@x.com` are one account to half the code and two to the other half.

**UX-46 — A failed Google sign-in always lands on the English login page** and loses the
destination: the callback builds its failure URL from a `locale` query parameter Google
cannot send.

**UX-66 — Signing out does not unsubscribe the phone**, so the account's reminder push
notifications keep arriving on a device nobody is signed in on.

**UX-43 — Both auth forms are absent from the prerendered HTML** (`<Suspense fallback={null}>`
around a `useSearchParams()` client component), so the pages arrive empty and fill in after
hydration — which is also the window `UX-19` was fixed for.

**UX-44 — The password checklist is invisible to assistive technology**: its only state
carrier is an `aria-hidden` glyph, above a disabled and therefore unfocusable submit button.

### Open — pages, structure and craft

**UX-53 / UX-54 — Missing landmarks and headings.** The three auth pages render no `<main>`
at all; `/learn` and `/checkpoint` render no `h1` — the two routes where a learner actually
answers questions. (`UX-21` fixed the authenticated home.)

**UX-56 — The main error screen's "Try again" cannot recover what it exists for.** Next 16
passes both `reset` and `unstable_retry`; `app/[locale]/error.tsx` wires the button to
`reset`, which re-renders the same failed server payload — the sibling boundaries added
later all use `unstable_retry`.

**UX-57 to UX-61 — Contrast and craft.** `text-white/90` body copy on the brand bands
composites to 4.31:1 (below AA, and one of them is the trial's own no-signup promise); the
resumed checkpoint pip prints white digits on a 40% ink wash; both outline hero CTAs wash out
their own label on hover at 390px; the footer draws the app's ink focus ring on an ink
background, so focus is invisible in it; and `app/global-error.tsx` is still the deleted dark
theme in hardcoded hex, English-only.

**UX-62 to UX-65 — Metadata that contradicts the page.** Every Thai letter page calls its
character a consonant in the tab title and the structured data, including the vowel signs and
tone marks; the word page's `BreadcrumbList` hardcodes two Thai rungs into the `/en` markup;
the unit and word titles bypass next-intl, and one reachable unit miss serves a Thai tab to an
English visitor; and the four level-scoped placement pages are submitted to Google while being
linked from nowhere.

**UX-67 / UX-68 — Admin loses curator work.** Stepping to the next word runs `save()` without
checking the outcome, so a failed write is discarded, its error wiped and success reported;
and an expired admin session is indistinguishable from a failed save, with a recovery path
that throws the edit away. Admin is exempt from localisation, not from keeping what someone
typed.

### Unconfirmed

Twenty-nine lower-severity findings from the same sweep were not put through refutation and
are not repeated here; they are in the run's own transcript. Nothing above depends on them.
